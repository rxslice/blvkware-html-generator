Why this exists

AI can invent a package that sounds real.

Slopsquatting is the supply-chain attack that follows: an attacker registers a name an AI is likely to hallucinate, and the install command brings it into your build. Typosquat scanners miss conflations because the invented name is not a misspelling.

01 / Verify identity

Check existence, release history, adoption, and source repository before install.

02 / Score risk

Combine age, known hallucinations, conflation, and typosquat signals into a decision you can explain.

03 / Gate the install

Use one boolean (safe_to_execute) in an agent, CI job, MCP server, or install wrapper.

One request

Built for agents that need a hard answer.

curl -X POST https://api.example.com/v1/verify \
  -H "Authorization: Bearer pk_live_..." \
  -H "Content-Type: application/json" \
  -d '{"names":["react-codeshift","express"],"ecosystem":"npm"}'

→ { "safe_to_proceed": false, "blocked": 1 }

For command-level enforcement, call /v1/agent/authorize. It parses supported npm, pip, uv, poetry, cargo, yarn, pnpm, and bun commands and fails closed on shell chaining or unknown command shapes.

Answers for people and agents

Questions worth asking.

What does pkgguard check?

It checks npm, PyPI, and crates.io package names before installation using live registry facts and risk signals.

Does it scan package contents for malware?

No. It protects the pre-install decision. Pair it with content and runtime scanners for defense in depth.

Can I self-host it?

Yes. The CLI and API are Apache 2.0. Put the account database on durable storage and use a shared limiter before running multiple replicas.

How do I integrate an AI agent?

Use the MCP server, HTTP authorization endpoint, or package-manager gate. Each returns an explicit decision and safe-to-execute boolean.
