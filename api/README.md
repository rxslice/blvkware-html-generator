# Checkout

One serverless function. It turns a configured order into a Stripe Checkout
Session so a buyer can pay at 11pm without anyone being awake.

GitHub Pages is static and cannot run it, which is why this directory sits
outside `docs/` and deploys separately.

## The property that matters

**The price is never taken from the request.** The browser sends a
specification; `checkout.js` re-derives the entire quote from the catalog using
the same engine the configurator uses, and charges that. Anyone can open
devtools and change what the page sends, so a client-supplied amount is a claim
to be checked, not an instruction.

If the recomputed price disagrees with what the buyer was shown, the order is
**refused** rather than quietly charged at the correct figure. Someone charged
an amount they never saw will dispute it, and they would be right to.

`_catalog.json` and `_engine.js` are generated by `dev/build-static.py` from
`dev/catalog.py` and `dev/engine.js`. Do not edit them, and do not let this
directory keep its own copy of a price — that drift is the whole thing this
arrangement exists to prevent.

## Deploying it (about ten minutes)

Any Node serverless host works. Vercel is the shortest path:

```bash
cd blvkware-html-generator
npm init -y && npm install stripe          # creates package.json
npx vercel                                  # first deploy, follow the prompts
npx vercel env add STRIPE_SECRET_KEY        # paste the LIVE key (sk_live_...)
npx vercel env add PUBLIC_BASE_URL          # https://blvkware.dev
npx vercel env add ALLOWED_ORIGIN           # https://blvkware.dev
npx vercel --prod
```

Vercel serves the file at `https://<project>.vercel.app/api/checkout`.

Then point the site at it — one line in `site/hire.html`:

```js
var CHECKOUT_ENDPOINT = "https://<project>.vercel.app/api/checkout";
```

Rebuild (`python dev/build-static.py`), commit, push. **Until that line is set
the Pay button never appears** and orders complete by email exactly as they do
today. The page never offers a payment it cannot take.

## Test it before going live

Use a test key (`sk_test_...`) and card `4242 4242 4242 4242`, any future
expiry, any CVC. Walk the whole path: configure at `/hire/`, pay, land back on
`/hire/?paid=1&ref=…`, and check the specification comes back and "Open it in
the Forge" carries it into SIGIL.

Then try to break it: edit `commercial.build` in devtools before paying. The
function must answer **409** and charge nothing.

## What is deliberately not here

**No webhook, and no order database.** A webhook would mean running state, and
the honest answer at one customer a week is that Stripe's own dashboard is the
order list and the buyer's emailed specification is the record. Add a webhook
when the volume makes the dashboard tedious — not before, because a database
nobody reconciles is worse than no database.

**Subscriptions are not created here.** The session charges the build plus the
first month or year. Agent Operations is set up as a Stripe subscription by hand
when the agent actually goes live, which is the honest moment to start billing
for something that is running.
